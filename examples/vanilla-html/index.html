4 · Type-specific attributes

k=v attributes carry per-type config: rows/cols for tables, progress 0–100, fontSize, badgeColor, alertColor.

4b · Real data in navbar / tabs / table / pagination

Four built-ins accept content attributes so you don't have to live with placeholder data. navbar items=, tabs active=, table headers=/data=, pagination current=/total=.

Show source 
element navbar 0 0 900 44 "Acme" items="Docs|API|Pricing|Blog"
element tabs 0 60 900 80 "Inbox content area" tabNames="Inbox|Sent|Drafts|Spam" active=2
element table 0 160 540 160 "" headers="Name|Email|Role" data="Jane|jane@x.com|Admin;John|john@y.com|User;Sam|sam@z.com|Guest"
element pagination 560 280 340 32 "" current=4 total=20

7 · Layout primitives — row and col

Stop hand-computing X/Y. row stacks children left-to-right, col top-to-bottom. gap is the spacing, align controls perpendicular placement (start | middle | end; col also supports stretch).

Show source 
row 20 70 660 36 gap=8 align=middle
  element button 0 0 100 36 "Profile"
  element button 0 0 100 36 "Account"
  element button 0 0 100 36 "Notifications"
  element button 0 0 100 36 "Billing"
end

col 20 130 320 160 gap=10 align=stretch
  element card 0 0 0 70 "User"
  element card 0 0 0 70 "Plan"
end

8 · Sticky-note annotations

10 · Slot text instead of code attribute

If you'd rather not stuff the DSL into an attribute string, put it inside the element. The code attribute takes precedence; slot text is the fallback.

element navbar 0 0 500 44 "Slotted" element label 20 70 460 24 "This wireframe came from textContent, not an attribute."

11 · Composite components

Define a reusable widget once, reference it many times. Inside the body, $name / ${name} placeholders pull values from the call site. Component bodies use coordinates relative to the component's origin; the parser translates them at expansion.

Show source 
component user-card(name, role, status)
  element card 0 0 220 80 ""
  element avatar 8 12 56 56 ""
  element heading 76 10 140 24 "$name"
  element label 76 36 140 18 "$role"
  element badge 76 56 60 18 "$status"
end

element user-card 20 60 220 80 "" name="Jane Doe" role="Engineering Lead" status="ACTIVE"
element user-card 250 60 220 80 "" name="John Roe" role="Product Designer" status="AWAY"
... (six instances total)

13 · <boceto-edit>

Same renderer as <boceto-view> — the editor's interactive layer (drag / resize / multi-select / undo) lands in a future release. The component already exposes the stable API (code attribute, change event) so wiring it up today keeps working.
